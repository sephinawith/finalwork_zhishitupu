# 问答系统设计说明

## 1. 模块定位

本模块负责课程大作业中的“问答系统”部分。系统不进行 ctext/cbdb 知识补充，而是基于小组已经构建好的 RDF/Turtle 知识图谱，实现自然语言问答、工具调用、SPARQL 查询和网页展示。

## 2. 总体流程

用户输入自然语言问题后，系统经过以下流程生成答案：

```text
用户问题
  -> 问题解析
  -> 工具路由
  -> 本地工具查询或 SPARQL 查询
  -> 查询证据整理
  -> 自然语言答案生成
  -> 网页展示答案、SPARQL 和证据
```

## 3. LangGraph 风格工作流

系统按照 LangGraph 的思想拆分为多个节点：

- `question_analyzer`：识别用户问题中的人物、流派和查询意图。
- `tool_router`：判断问题适合调用本地工具还是高级 SPARQL。
- `tool_executor`：执行人物字号、关系、流派成员等确定性查询工具。
- `sparql_executor`：执行用户输入或系统生成的 SPARQL 查询。
- `answer_generator`：将结构化查询结果组织成中文答案。
- `fallback_handler`：当实体不存在或查询为空时给出明确提示。

这种设计可以避免所有问题都直接交给大模型，从而提高查询准确性和可解释性。

## 4. 已实现工具

系统封装了以下本地工具：

- `get_person_basic_info(name)`：查询人物基本信息，如字、号、生卒年、朝代、身份、所属流派。
- `get_person_alias(name)`：查询人物的字和号。
- `get_person_relations(name, relation_type)`：查询人物的亲属、师承、交游、流派等关系。
- `get_relation_between_people(person1, person2)`：查询两个人之间的直接关系。
- `get_school_members(school)`：查询某一流派中的人物。
- `run_sparql_query(query)`：执行高级 SPARQL 查询。

## 5. 支持的问题类型

系统支持以下类型的问题：

- 人物属性查询：文彭的字号是什么？
- 人物基本信息查询：文彭的基本信息是什么？
- 人物关系查询：文彭和文徵明是什么关系？
- 师承关系查询：文彭的师承关系有哪些？
- 交游关系查询：哪些人与文彭有交游关系？
- 流派成员查询：吴门印派有哪些人物？
- 高级查询：用户直接输入 SPARQL 语句。

## 6. 网页前端功能

网页前端包含以下区域：

- 自然语言查询输入框。
- 示例问题按钮。
- 自然语言答案展示区。
- 查询证据表格。
- 生成的 SPARQL 展示区。
- 高级 SPARQL 查询界面。
- 工作流节点追踪展示。

## 7. 可解释性设计

系统不仅返回答案，还展示：

- 查询使用的 SPARQL。
- 命中的三元组证据。
- 工作流每一步的节点状态。

因此用户可以看到答案来自哪些知识图谱事实，减少大模型幻觉问题。

## 8. 与小组其他部分的衔接

本模块读取 `data/kg.ttl` 作为知识图谱输入。小组成员完成知识抽取后，只需要将最终 Turtle 文件替换该文件即可接入问答系统。如果本体谓词发生变化，只需在 `server.js` 中调整关系谓词映射和工具查询逻辑。

## 9. 运行方式

进入项目目录后运行：

```powershell
node server.js
```

或直接双击：

```text
start_server.bat
```

然后访问：

```text
http://localhost:3000
```
